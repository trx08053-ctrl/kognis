# Решения, принятые ночью по поручению владельца (для утреннего ревью)

> Владелец (jusk-one) 2026-09-28 поручил: «решай сам как технический ответственный, утром — ревью».
> Не делается без владельца: деплой в прод, внешние сервисы/аккаунты, платные функции, реальные вызовы ИИ с
> ключом владельца. Каждое решение ниже можно пересмотреть — так и помечено в ADR.

## D1. Архитектура (ADR 0002 — Accepted)
Модульный монолит. Модули и направление зависимостей (`.importlinter`, выше может использовать ниже):

```
web
analysis | gameplay          (независимы друг от друга)
diary
ai | safety | access         (независимы друг от друга)
users
db
```

Добавлен модуль **safety** (кризисные сигналы, контакты помощи) — требование заказчика, отдельная ответственность.

## D2. Межмодульные эффекты — оркестрация в `web`
XP за запись, квесты из результатов анализа и т. п. связывает слой `web` (сценарии приложения), модули не знают
друг о друге. Шина событий — когда потребителей эффекта станет ≥ 3 (рекомендации, уведомления), отдельным ADR.

## D3. Аутентификация и сессии (ADR 0003)
- email + пароль (≥ 8 символов), хэш **argon2id** (`argon2-cffi`); email нормализуется (lower, trim).
- Сессия: случайный токен (32 байта) в cookie `kognis_session` — httpOnly, SameSite=Lax, Secure вне dev;
  в БД хранится только SHA-256 токена (таблица `sessions`, владелец `users`); срок 30 дней; выход удаляет сессию.
- CSRF: SameSite=Lax + изменяющие запросы только с `Content-Type: application/json`.
- Каждый запрос к данным фильтруется по владельцу; чужая запись → 404 (не 403), чтобы не раскрывать существование.
- Ограничение попыток входа — отдельной задачей (hardening).

## D4. Записи и защита (ADR 0003)
- Запись: дата (локальная дата пользователя), текст, теги, эмоции (из словаря + свои), режим защиты.
- `plain` — обычная.
- `locked` — «под замком»: текст шифруется на сервере AES-GCM (`cryptography`) ключом данных `KOGNIS_DATA_KEY`
  (base64, 32 байта; в dev генерируется и пишется в `.deploy`/env, в проде — из секретов); пароль замка — argon2id.
  Открывается на время запроса; к ИИ — только с явного согласия на конкретный анализ.
- `private` — «приватная»: шифруется в браузере (WebCrypto: PBKDF2-SHA256 600 000 итераций → AES-GCM-256);
  сервер хранит шифртекст, iv, соль, параметры KDF и версию формата; сервер и ИИ не могут прочитать.
  Интерфейс явно предупреждает: забытый пароль = потеря записи.

## D5. Безопасность пользователя — модуль safety
Детерминированный локальный детектор кризисных сигналов (фразы RU/EN) — до любого ИИ. При срабатывании: ответ
содержит блок помощи, запись не даёт XP и не порождает квестов, анализ вместо паттернов даёт поддерживающее
сообщение. Контакты — данные-конфигурация; по умолчанию **112**. **Владельцу: проверить и дополнить список
горячих линий утром** (не хочу выдумывать номера).

## D6. ИИ-провайдер — модуль ai
Протокол `AiProvider`: `complete(system, messages, schema?) -> str`. Реализации: `FakeProvider` (детерминированный,
тесты и dev по умолчанию) и `OpenAICompatibleProvider` (httpx; `KOGNIS_AI_BASE_URL`, `KOGNIS_AI_MODEL`,
`KOGNIS_AI_API_KEY`) — покрывает Ollama Cloud (DeepSeek), локальный vLLM/Qwen и др. Ключ не логируется.
Реальный вызов с вашим ключом ночью не делаю (R3 — утром).

## D7. Анализ — модуль analysis
Направления — данные-конфигурация: КПТ, ACT, схема-терапия, позитивная психология, поведенческая активация.
Ответ модели — строгий JSON (pydantic): резюме, паттерны (с цитатами-опорами из записей), уточняющие вопросы,
предложения квестов. Динамика настроения считается локально (без ИИ). Согласие на передачу записей — на каждый
анализ. Результаты сохраняются (`analyses`). Везде дисклеймер «не медицинская помощь».

## D8. Игровая механика — модуль gameplay
XP: запись +10 (до 3 в день), итог дня +20, шаг квеста +15, квест +50, квиз-рефлексия +10. Уровни по таблице.
Серия (streak) — подряд дни с записью или итогом дня; 1 «заморозка» в неделю; без наказаний сверх сброса.
Достижения и квесты — данные-конфигурация (библиотека) + квесты, предложенные анализом. Прогресс сохраняется.

## D9. Доступ к функциям — модуль access
`can_use(user, feature) -> bool` (сейчас всегда `True`), список функций — перечисление. Точки платных функций
(ИИ-анализ, Advanced-графики) уже вызывают `can_use` — тарифы позже без переделки.

## D10. Интерфейс
React Router, TanStack Query, Tailwind CSS v4, Recharts (Advanced-графики). Тёмная тема: системная + переключатель
(класс `dark`, выбор в localStorage). Простой режим по умолчанию, Advanced — переключатель в профиле (хранится на
сервере). Язык — русский, строки собраны в одном месте. Доступность — axe без serious/critical.

## D11. Время
Метки — UTC; «дата записи» — локальная дата пользователя (часовой пояс в профиле, по умолчанию Europe/Moscow).

## Зависимости, добавленные владельцем-делегатом
Python: `argon2-cffi`, `cryptography`, `httpx`. Frontend: `react-router`, `@tanstack/react-query`, `recharts`,
`tailwindcss`, `@tailwindcss/vite` (+ плагин в `vite.config.ts`, `css.parser.tailwindDirectives` в Biome).

## Порядок задач
U1 (аккаунт + запись, задача kognis-b8z) → итог дня → игровое ядро → safety → ai → анализ → квесты/квизы →
замок → приватные записи → интерфейс (тема, режимы, дашборд) → hardening. Все — в `bd` с зависимостями.
