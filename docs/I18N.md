# Мультиязычность

Сайт с первого дня готов к переводу: текст для человека живёт в словарях, код оперирует ключами и кодами.
Добавить язык = добавить словарь, а не переписывать интерфейс. Проверка `i18n` в `just verify` ловит текст
прямо в коде. Урок kognis: без этой основы подготовка к переводу стоила бы правки почти каждого файла
(≈ 600 строк текста), и дороже с каждой новой функцией.

## Правила
1. **Текст — только в словарях.** Интерфейс: `t("ключ")` из `useI18n()`; словари
   `frontend/src/i18n/<язык>.ts`. Базовый словарь — `ru.ts`; остальные имеют тип `Catalog`, поэтому TypeScript
   не соберёт проект, если в языке не хватает ключа.
   Ключи — по смыслу и области: `users.title`, `error.user.name_empty`.
2. **Сервер отдаёт коды, а не фразы.** Ошибка для пользователя — исключение домена с полем `code`;
   API отвечает `{"detail": {"code": "user.name_empty"}}`, текст берётся из словаря интерфейса по ключу
   `error.<код>`; неизвестный код → общий текст. Служебные строки кода (логи, исключения для разработчика) —
   по-английски.
3. **Параметры и множественное число** — не склеивать строки: `t("users.count", { count })`; формы
   множественного числа по `Intl.PluralRules` (у русского `one/few/many/other`, у английского `one/other`,
   у арабского шесть форм).
4. **Даты, числа, валюты** — только через `Intl` с языком пользователя (`formatDate`, `formatNumber`), не
   вручную (`01.02` vs `2/1`, `1 234,5` vs `1,234.5`).
5. **Язык пользователя:** сохранённый выбор → язык браузера → язык по умолчанию. После входа — хранить в профиле
   (поле `locale`), чтобы письма и уведомления шли на нём же.
6. **Направление письма:** `<html lang dir>` выставляется по языку; в CSS — логические свойства
   (`margin-inline-start`, `padding-inline-end`, `text-align: start`), а не `left/right`. Тогда язык справа
   налево (арабский, иврит) не ломает вёрстку.
7. **Название продукта, имена, пользовательские данные** не переводятся (константа `APP_NAME`).

## Что переводом не решается (решает человек)
- **Контент со смыслом** — тексты методик, подсказки, квесты: адаптация носителем, а не машинный перевод.
- **Безопасность и право по странам:** телефоны помощи, согласия, политика конфиденциальности, возрастные
  ограничения — свои для каждой страны. Не включать язык, пока этот контент не проверен.
- **ИИ-функции:** промпт просит отвечать на языке пользователя; набор оценки качества (`evals/`) — на каждом
  языке, прогон на настоящей модели до включения языка.

## Добавить язык
1. `frontend/src/i18n/<код>.ts` с типом `Catalog`; строка в `CATALOGS` и `LOCALE_NAMES`
   (`frontend/src/i18n/index.tsx`).
2. Переводы проверяет носитель; скриншоты ключевых экранов на этом языке (`just shot`, браузер с `locale`).
3. Для языка справа налево — скриншоты всех экранов: зеркальность, иконки со стрелками, графики.
4. Контент из раздела «Что переводом не решается» — готов и проверен.

## Существующий проект (переход)
Проверка `i18n` сразу найдёт весь текст в коде. Человек один раз фиксирует его как долг перевода:
`just i18n-adopt` (hook спросит подтверждение) — находки попадают в `.quality-baseline.json`
(`i18n_hardcoded`). Новые находки запрещены; вынесенные в словарь уходят из планки при `just ratchet-up`.
Выносить текст — по областям (страница, модуль) отдельными задачами.

## Ограничения проверки
Английский текст в Python и в строках TypeScript вне JSX не распознаётся (нельзя отличить от идентификаторов);
текст с буквами не-латиницы ловится везде. Поэтому правило 2 (коды вместо фраз) проверяет ещё и ревьюер.
