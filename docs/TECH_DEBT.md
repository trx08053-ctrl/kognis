# Технический долг

Каждый осознанный компромисс записывается сюда со ссылкой на задачу `bd`.

| ID | Где | Что не так | Почему так | Риск | Задача |
|---|---|---|---|---|---|
| TD-1 | users/web (вход) | нет ограничения попыток входа | отдельная задача hardening, ADR 0003 | перебор паролей | kognis-yaj |
| TD-2 | diary | дата записи по умолчанию — UTC сервера (через HTTP `web` подставляет локальную дату, см. TD-5), а не пояс профиля (D4/D11) | часовой пояс профиля — позже | запись вечером попадает не в тот день | kognis-7cn |
| TD-3 | users | просроченные сессии не удаляются | не критично на старте | рост таблицы `sessions` | kognis-yaj |
| TD-5 | web/gameplay | «сегодня» для серии дней — константа Europe/Moscow (`local_today`), а не часовой пояс профиля; у пользователя пояса ещё нет (D11); кризисные итоги дня опыт тоже дают (см. TD-4) | часовой пояс профиля — отдельной задачей вместе с TD-2 | серия «ломается» у пользователя вне пояса Москвы около полуночи | kognis-50k |
| TD-6 | analysis | цитаты паттернов не сверяются с текстом записей; теги/эмоции уходят провайдеру без кризисной проверки; записи фильтруются по периоду в Python, размер текста не ограничен; повторный запуск на кризисном периоде каждый раз добавляет строку `crisis` | минимум для первой версии, ревью kognis-kai | выдуманная цитата в UI; большой запрос к провайдеру | kognis-kai |
| TD-7 | gameplay | «квест уже принят» проверяется до вставки, без ограничения в БД: два параллельных принятия одного квеста создадут дубль (и XP за шаги дубля); кризисный ответ квиза занимает суточный слот без XP | редкая гонка, для библиотеки нужен частичный индекс по незавершённым; ревью kognis-99x | двойной XP при двойном клике «Принять» в разных вкладках | kognis-99x |
| TD-4 | safety/web | кризисный сигнал ищется в записи (текст, теги, эмоции) и в рефлексии «Итога дня» (kognis-cdu; флага кризиса у итога нет — уже начисленный XP не отзывается); список фраз намеренно небольшой (без ИИ), возможны пропуски | границы kognis-d5q; список растёт по примерам | пропуск сигнала | kognis-cdu |
| TD-8 | diary/deploy | `KOGNIS_DATA_KEY` (D4) читается из окружения, но `just stage`/`deploy` его не генерируют и не передают (конфиги развёртывания — решение человека); лимит неверных паролей замка (5 за 5 минут на запись) хранится в памяти процесса — сбрасывается перезапуском и не общий между воркерами; теги/эмоции закрытых записей не шифруются; AAD шифртекста не включает id записи; смена режима записи в интерфейсе — только создание с замком, `lock`/`unlock` доступны лишь через API | границы kognis-83s: конфиги деплоя вне задачи, hardening — отдельно | без ключа замок отвечает 503; перебор пароля замка сессией владельца | kognis-83s |
