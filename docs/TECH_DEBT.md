# Технический долг

Каждый осознанный компромисс записывается сюда со ссылкой на задачу `bd`.

| ID | Где | Что не так | Почему так | Риск | Задача |
|---|---|---|---|---|---|
| TD-1 | users/web (вход) | лимит по IP берёт адрес соединения (за прокси — адрес прокси); блокировка по email позволяет намеренно запереть чужой аккаунт на 15 минут; проверка и учёт попытки — отдельные запросы к БД, при параллельной пачке возможен небольшой перерасход | прокси в стеке пока нет; kognis-yaj | блокировка всех входов за прокси; DoS на конкретного пользователя | kognis-yaj; kognis-h1y (IP за прокси); запирание чужого аккаунта — пересмотр 2026-12-31 |
| TD-2 | diary | дата записи по умолчанию — UTC сервера (через HTTP `web` подставляет дату по поясу профиля, kognis-1yv), а не пояс профиля (D4/D11) | передавать пояс профиля в `diary` — позже | запись вечером попадает не в тот день | kognis-7cn; пересмотр 2026-12-31 |
| TD-3 | users | просроченные сессии не удаляются | не критично на старте | рост таблицы `sessions` | kognis-yaj; пересмотр 2026-12-31 |
| TD-5 | web/gameplay | кризисные итоги дня опыт тоже дают (см. TD-4); «сегодня» теперь по поясу профиля (kognis-1yv), у `diary` при прямом вызове без даты по-прежнему UTC (TD-2) | см. TD-4 | — | kognis-50k; вместе с TD-4; пересмотр 2026-12-31 |
| TD-6 | analysis | цитаты паттернов не сверяются с текстом записей; теги/эмоции уходят провайдеру без кризисной проверки; записи фильтруются по периоду в Python, размер текста не ограничен; повторный запуск на кризисном периоде каждый раз добавляет строку `crisis` | минимум для первой версии, ревью kognis-kai | выдуманная цитата в UI; большой запрос к провайдеру | kognis-kai; пересмотр 2026-12-31 |
| TD-7 | gameplay | «квест уже принят» проверяется до вставки, без ограничения в БД: два параллельных принятия одного квеста создадут дубль (и XP за шаги дубля); кризисный ответ квиза занимает суточный слот без XP | редкая гонка, для библиотеки нужен частичный индекс по незавершённым; ревью kognis-99x | двойной XP при двойном клике «Принять» в разных вкладках | kognis-99x; kognis-4ku |
| TD-4 | safety/web | кризисный сигнал ищется в записи (текст, теги, эмоции) и в рефлексии «Итога дня» (kognis-cdu; флага кризиса у итога нет — уже начисленный XP не отзывается); список фраз намеренно небольшой (без ИИ), возможны пропуски | границы kognis-d5q; список растёт по примерам | пропуск сигнала | kognis-cdu; детектор отключён (решение 2026-09-30) — пересмотр при включении по языкам, не позже 2026-12-31; пересмотр 2026-12-31 |
| TD-8 | diary/deploy | `KOGNIS_DATA_KEY` (D4) читается из окружения, но `just stage`/`deploy` его не генерируют и не передают (конфиги развёртывания — решение человека); лимит неверных паролей замка (5 за 5 минут на запись) хранится в памяти процесса — сбрасывается перезапуском и не общий между воркерами; теги/эмоции закрытых записей не шифруются; AAD шифртекста не включает id записи; смена режима записи в интерфейсе — только создание с замком, `lock`/`unlock` доступны лишь через API | границы kognis-83s: конфиги деплоя вне задачи, hardening — отдельно | без ключа замок отвечает 503; перебор пароля замка сессией владельца | kognis-83s; kognis-kmd |
| TD-9 | diary | `entry_labels` читает теги и эмоции всех записей владельца и собирает множества в Python (O(n)); индекс `ix_entries_owner_id` избыточен после `ix_entries_owner_date_id`; фильтр по метке в PostgreSQL не использует индекс | для года данных (1095 записей) укладывается в бюджет; kognis-3mh | рост времени `/api/entries/labels` на многолетнем дневнике | kognis-3mh; пересмотр 2026-12-31 |
| TD-10 | analysis/web | история разборов постраничная по `offset`: если между запросами страниц разбор добавили или удалили, страницы сдвигаются (возможен дубль строки на следующей странице) | limit/offset — по постановке kognis-qkh; курсор по `id` — позже | повторяющийся `key` в списке, лишняя строка | kognis-qkh; пересмотр 2026-12-31 |
| TD-11 | gameplay | каталог достижений `_achievements.py` не входит в мутационную проверку (мутируются только `_domain.py`/`_app.py`); потолок 60 XP/день проверяется до вставки — при параллельных запросах возможен небольшой перерасход; достижения «Исследователя» у существующих пользователей начинаются с нуля | `scripts/check_mutation.py` — проверка, менять её решает человек; потолок ограничен уникальностью событий | пропуск поломки порогов достижений; лишние XP при гонке | kognis-0a8; пересмотр 2026-12-31 |
