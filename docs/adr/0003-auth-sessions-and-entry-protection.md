# 0003. Аутентификация, сессии и защита записей

- **Статус:** Accepted (jusk-one по делегированию, 2026-09-29; см. docs/DECISIONS-NIGHT.md D3–D4)
- **Дата:** 2026-09-29 · **Задача:** kognis-b8z

## Контекст
Данные — чувствительные; пользователь должен видеть только своё; часть записей должна быть недоступна серверу и ИИ.

## Варианты
1. Серверные сессии в cookie + пароль argon2id.
2. JWT в localStorage — уязвим к XSS, сложнее отзыв.

## Решение
Вариант 1. email + пароль (≥ 8 символов), argon2id (`argon2-cffi`), email нормализуется. Сессия — случайный токен
(32 байта) в cookie `kognis_session` (httpOnly, SameSite=Lax); в БД только SHA-256 токена (`sessions`, владелец
`users`), срок 30 дней, выход удаляет сессию. CSRF: SameSite=Lax + изменяющие запросы только `application/json`.
Каждый запрос к данным фильтруется по владельцу; чужая запись → 404. Режимы защиты записи: `plain` (U1),
`locked` (AES-GCM ключом сервера + пароль замка), `private` (шифрование в браузере, WebCrypto PBKDF2→AES-GCM) —
последние два реализуются отдельными задачами.

## Проверка результата
Приёмочный тест U1 (AC2): изоляция между пользователями по API и в интерфейсе.

## Последствия
- **Минусы:** ограничение попыток входа добавлено в kognis-yaj (5 на email / 20 на IP за 15 минут, в БД); за прокси нужен корректный IP клиента; забытый пароль «приватной» записи = потеря.
- **Когда пересмотреть:** появление SSO/мобильных клиентов.
