# Модуль `analysis`

> Ссылки на код — `` `src/<пакет>/<модуль>/<файл>.py::<символ>` `` (проверяет `just check refs`).
> Публичные символы и фактические зависимости генерируются: `just context analysis` / `docs/MAP.md`.

- **Назначение:** анализ периода записей по направлению психологии через ИИ (резюме, паттерны с опорой на записи,
  уточняющие вопросы) и динамика настроения без ИИ; сам не ходит в сеть — провайдер приходит из `ai`.
- **Публичный API:** только `src/kognis/analysis/__init__.py` (`__all__`); файлы `_*.py` — внутренности.

## Бизнес-правила
- Направления — данные `DIRECTIONS` (КПТ, ACT, схема-терапия, позитивная психология, поведенческая активация)
  (`src/kognis/analysis/_domain.py::DIRECTIONS`).
- Согласие на передачу записей — на каждый анализ и на каждый набор ответов; без него провайдер не вызывается
  (`src/kognis/analysis/_app.py::AnalysisService.analyze`).
- Записи и итоги дня за период берутся выборкой `DiaryService.list_*_between` (фильтр в БД).
- Передаются только записи режима `plain` за период и итоги дня; защищённые/приватные — никогда (D4).
- Кризис (safety) в записях, рефлексии или ответах — только при включённом `KOGNIS_CRISIS_DETECTOR=on`: провайдер
  не вызывается, вместо паттернов — статус `crisis` и блок помощи. Проверка идёт до проверки согласия. По умолчанию
  детектор выключен (kognis-xci, риск R4): анализ идёт обычным порядком, а страховка — инструкция в промпте
  (`src/kognis/analysis/_prompts_i18n.py::SAFETY_CLAUSE`): при угрозе жизни не разбирать как паттерн, бережно
  предложить близкого человека или экстренные службы своей страны, без диагнозов. Записи, ранее помеченные
  `entries.crisis`, по-прежнему дают статус `crisis`.
- Ответ модели — строгий JSON (`AnalysisResult`, лишние поля запрещены), опоры `entry_ids` обязаны быть среди
  переданных записей; невалидный ответ — один повтор, затем `AnalysisFailedError` с понятным текстом.
- Период — до 31 дня (`MAX_PERIOD_DAYS`, код `analysis.period_long`); не более 100 записей уходит провайдеру (последние).
- Бюджет текста на запрос — `TEXT_BUDGET` 24 000 символов: запись ≤ 1 500, рефлексия итога дня ≤ 500 (с пометкой «…»);
  при превышении самые длинные урезаются до общего порога, короткие целые (`src/kognis/analysis/_domain.py::fit_texts`, детерминированно).
- Период по умолчанию (`AnalysisService.default_period`, `GET /api/analyses/period`): день после конца последнего
  завершённого разбора (любого направления) … сегодня по поясу профиля; без разборов — последние 7 дней; больше 31
  дня — последние 31 (`truncated`); нет записей и итогов дня за период или сегодня уже разбирали — `active: false`.
- Дубль: завершённый разбор того же направления и периода (не продолжение) → `DuplicateAnalysisError`,
  409 `analysis.duplicate` с `existing_id`; проверяется после кризисного сигнала (поддержка важнее экономии).
- Преемственность (ADR 0005): модель получает `memory` (дайджест ≤ 2 000) и `previous_analysis` (итог прошлого разбора
  этого направления ≤ 1 500), но не старые записи; ответ содержит `changes` (≤ 5) и `memory`. Дайджест сохраняется в
  `analysis_memory` и не хранится в `result`. «Что ИИ помнит»: `GET|DELETE /api/analyses/memory`; память очищается и
  при удалении последнего разбора (пока остался любой, включая кризисный, память сохраняется). Защищённые/приватные записи в анализ не уходят, поэтому цитат из них в памяти нет.
- Динамика настроения — средние и тренд (вторая половина против первой, порог 0,5) из итогов дня,
  `src/kognis/analysis/_domain.py::mood_dynamics`.
- История: `AnalysisService.history` — страница (`limit` ≤ 100, `offset`), новые первыми; `AnalysisPage.next_offset`
  — смещение следующей страницы или `None`. Удаление `AnalysisService.delete` — только своего, чужой неотличим от
  несуществующего; у продолжений `parent_id` остаётся без родителя (без внешнего ключа), они самодостаточны
  (kognis-qkh).
- Продолжение: ответы на вопросы порождают новый анализ с `parent_id`; кризисный анализ продолжать нельзя.
