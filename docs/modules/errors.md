# Модуль `errors`

> Ссылки на код — `` `src/<пакет>/<модуль>/<файл>.py::<символ>` `` (проверяет `just check refs`).
> Публичные символы и фактические зависимости генерируются: `just context errors` / `docs/MAP.md`.

- **Назначение:** общий тип ошибки для показа человеку — код и параметры вместо фразы (docs/I18N.md, правило 2).
  Не содержит текстов и не знает про HTTP: текст по коду берёт интерфейс, HTTP-ответ строит `web`.
- **Публичный API:** `src/kognis/errors.py::CodedError`, `src/kognis/errors.py::CodedValueError` (наследует `ValueError`).
- **Термины и синонимы:** код ошибки, error code, coded error, i18n, локализация ошибок.
- **Сценарии:** домен модуля бросает `CodedValueError("diary.text_empty")` → `web` отвечает
  `{"detail": {"code": "diary.text_empty", "params": {}}}` → фронтенд показывает `error.diary.text_empty` из словаря.
- **Точки входа:** нет (библиотечный код); ответы API строит `src/kognis/web/_errors.py::http_error`.

## Бизнес-правила (инварианты)
- Код — `область.причина` в нижнем регистре; каждый код, который может уйти наружу, есть в
  `frontend/src/i18n/ru.ts` как `error.<код>` (проверяет `tests/web/test_error_codes.py`).
- Сообщение исключения — код (служебное); текст для человека в исключениях и логах не хранится.
- Параметры — только значения для подстановки (числа, имена хостов), без пользовательских данных и секретов.
