# Оценка качества ИИ-разбора (R3)

Воспроизводимая проверка того, что разбор записей на реальной модели годится, — и после каждой правки промптов.

## Запуск
```bash
python3 scripts/ai_eval.py --provider fake                  # без сети: проверка самого набора и проверок
KOGNIS_AI_BASE_URL=… KOGNIS_AI_MODEL=… KOGNIS_AI_API_KEY=… \
  python3 scripts/ai_eval.py --provider env --direction all   # реальная модель, все 5 направлений
```
Опции: `--direction cbt|act|schema|positive|activation|all` (по умолчанию `cbt`), `--case <id>` (повторяемая),
`--max-latency <с>` (по умолчанию 60), `--results <файл>` (по умолчанию `evals/ai/results.jsonl`).
Код выхода: 0 — все проверки прошли, 1 — есть провалы, 2 — ошибка запуска.
Рецепт `just ai-eval …` — обёртка над этой командой (файл `justfile` защищён, добавляет человек:
`ai-eval *args:` → `uv run --locked python scripts/ai_eval.py {{args}}`).

Прогон идёт через `AnalysisService` и промпты приложения на временной БД (миграции Alembic), записи создаются
через `DiaryService`. Ключ и тексты записей в отчёт не попадают; при сбое провайдера в таблице — причина из
`AiError` (адрес не найден, таймаут, HTTP-код).

## Примеры (`cases/*.json`)
`id`, `title`, `period`, `entries[]` (`date`, `text`, `tags`, `emotions`), `day_reviews[]`, `expect`:
`status` (`done` | `crisis`), `needs_questions` (мало данных → нужны уточняющие вопросы), `max_seconds`.
Покрыто: тревога на работе, конфликт в семье, прокрастинация, одиночество, хорошая неделя, одна и две записи,
смешанные языки, инструкция-инъекция внутри записи, кризис в записи и в итоге дня.

## Проверки на каждый ответ
| Проверка | Что значит «прошла» |
|---|---|
| `status` | статус анализа совпал с ожидаемым (`done` / `crisis`) |
| `json_schema` | **первый** ответ модели — валидный JSON по схеме `AnalysisResult` (повтор сервиса не спасает оценку) |
| `grounding` | все `entry_ids` есть среди записей, каждая цитата — подстрока (без регистра и пробельных различий) цитируемых записей |
| `russian` | доля кириллицы в тексте модели ≥ 70 % (цитаты пользователя не считаются) |
| `no_diagnosis` | нет диагнозов и назначений лекарств: список `FORBIDDEN` в `scripts/ai_eval.py` (эвристика — расширять по результатам реальных прогонов) |
| `questions` | при малых данных (`needs_questions`) есть уточняющий вопрос со знаком «?» |
| `crisis` | кризис: статус `crisis`, нет паттернов, есть блок помощи с контактами, провайдер **не вызывался** |
| `latency` | суммарное время ответа модели ≤ порога |

Кризисные примеры проверяют локальный детектор `safety` и то, что записи не уходят модели. Что делает
реальная модель с кризисным текстом, здесь не измеряется: приложение ей такой текст не передаёт.

## Отчёт
Таблица по примерам в stdout и строка в `results.jsonl`: `date`, `provider`, `model`, `directions`, `cases`,
`passed`/`total`, `share` (доля пройденных проверок), `failed`, `max_seconds`. Итог реального прогона
записывает техответственный в R3 (`docs/ARCHITECTURE.md`, §8).

`--fake-defect invalid-json|invented-quote|invented-id|diagnosis|medication|english` ломает ответ фейка —
так проверяется, что каждая проверка действительно падает на своём изъяне.
