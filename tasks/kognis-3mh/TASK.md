# TASK kognis-3mh: Производительность: постраничная выдача, измеримые НФТ, бюджеты perf

- **Тип:** standard · **Приоритет:** P1 · **Автор:** jusk-one (техответственный, нагрузочный замер) · **Дата:** 2026-09-29

## 1. Цель
Приложение остаётся быстрым, когда дневник ведут годами. Замер на staging с годом данных (1095 записей, 365
итогов): `GET /api/entries` отдаёт весь дневник — 1 МБ, p95 707 мс, 37 rps при 20 клиентах, и растёт линейно;
`GET /api/day-reviews` — все итоги сразу (p95 182 мс). Требования в ARCHITECTURE §6 неизмеримы.

## 2. Границы
- **Входит:** постраничная выдача записей и итогов дня (курсор или limit/offset, по умолчанию 30, максимум 100,
  сортировка по дате убыв.; фильтры записей — на сервере); фронтенд подгружает страницы («Показать ещё» /
  прокрутка), фильтры и Advanced-графики работают; `just api-types`; ARCHITECTURE §6 — таблица измеримых НФТ
  (шаблон harness): p95 ключевых сценариев на объёме «год работы пользователя», объём данных, RPO/RTO, чем
  проверяется; `scripts/seed_perf.py` — засев года данных на окружение (через API); бюджеты в НФТ и команды
  `just perf …` в RUNBOOK.
- **Не входит:** кэширование, горизонтальное масштабирование.

## 2a. Область влияния
- **Модули:** diary (выборка страницы), web, frontend, docs · **Данные:** индекс по (owner_id, entry_date) при необходимости — миграция
- **Что может сломаться:** список, фильтры, e2e дневника и итогов — сценарии должны остаться зелёными

## 3. Критерии приёмки
| # | Критерий | Как проверить |
|---|---|---|
| AC1 | Список записей и итогов отдаётся страницами (≤ 100), следующая страница продолжает без пропусков и повторов | приёмочный тест `@pytest.mark.acceptance("kognis-3mh", "AC1")` |
| AC2 | Фильтры по тегу/эмоции/датам работают на сервере и со страницами | приёмочный тест `@pytest.mark.acceptance("kognis-3mh", "AC2")` |
| AC3 | В интерфейсе видна первая страница и подгружаются следующие; e2e дневника зелёные | приёмочный e2e `@pytest.mark.acceptance("kognis-3mh", "AC3")` |
| AC4 | На staging с засеянным годом данных `just perf /api/entries` и `/api/day-reviews` — p95 ≤ 200 мс при 20 клиентах (результат в PROGRESS) | замер делает техответственный после задачи (в песочнице агента нет Docker) |
