# TASK kognis-83s: Записи «под замком» (шифрование на сервере)

- **Тип:** risky · **Приоритет:** P2 · **Автор:** jusk-one (техответственный, ночное делегирование) · **Дата:** 2026-09-29
- Решения, на которые опирается задача: `docs/DECISIONS-NIGHT.md`, ADR в `docs/adr/`.

## 1. Цель
Пользователь закрывает отдельные записи паролем: без пароля их содержимое не видно даже в его аккаунте.

## 2. Границы
- **Входит:** diary: режим locked (D4) — AES-GCM ключом KOGNIS_DATA_KEY, пароль замка argon2id, открытие по паролю на время запроса, смена режима записи; в списках — заглушка без текста; интерфейс: замок при создании/редактировании, ввод пароля для открытия.
- **Не входит:** передача в анализ (делается в задаче анализа только с согласием), восстановление забытого пароля замка.

## 2a. Область влияния
- **Модули:** diary, web, frontend · **Данные:** новые поля записи (шифртекст, nonce, хэш пароля, версия) — миграция
- **Что может сломаться:** вход и записи (U1), изоляция данных пользователей — регрессионные тесты должны остаться зелёными

## 3. Критерии приёмки
| # | Критерий | Как проверить |
|---|---|---|
| AC1 | Текст записи «под замком» в БД хранится только зашифрованным (проверка прямым чтением таблицы) | приёмочный тест `@pytest.mark.acceptance("kognis-83s", "AC1")` |
| AC2 | Без правильного пароля запись не открывается; неверный пароль — понятная ошибка, без раскрытия текста | приёмочный тест `@pytest.mark.acceptance("kognis-83s", "AC2")` |
| AC3 | Смена ключа данных в конфигурации без ключа делает записи нечитаемыми, но приложение не падает (понятная ошибка) | приёмочный тест `@pytest.mark.acceptance("kognis-83s", "AC3")` |
| AC4 | Нет регрессий, интерфейс проверен глазами (`just shot`) и axe | `just verify` |
