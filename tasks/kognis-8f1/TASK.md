# TASK kognis-8f1: Приватные записи: шифрование в браузере (WebCrypto)

- **Тип:** risky · **Приоритет:** P2 · **Автор:** jusk-one (техответственный, ночное делегирование) · **Дата:** 2026-09-29
- Решения, на которые опирается задача: `docs/DECISIONS-NIGHT.md`, ADR в `docs/adr/`.

## 1. Цель
Самые личные записи шифруются на устройстве: ни сервер, ни ИИ не могут их прочитать.

## 2. Границы
- **Входит:** frontend: WebCrypto PBKDF2-SHA256 600000 → AES-GCM-256, формат с версией, соль и iv; diary хранит непрозрачный шифртекст; интерфейс с явным предупреждением о невосстановимости; vitest на шифрование/дешифрование; e2e: запись создаётся и открывается в браузере.
- **Не входит:** синхронизация ключей между устройствами, восстановление пароля.

## 2a. Область влияния
- **Модули:** diary, frontend, web · **Данные:** поля шифртекста для режима private
- **Что может сломаться:** вход и записи (U1), изоляция данных пользователей — регрессионные тесты должны остаться зелёными

## 3. Критерии приёмки
| # | Критерий | Как проверить |
|---|---|---|
| AC1 | Сервер получает и хранит только шифртекст: в запросах и БД нет исходного текста (проверка e2e через перехват запроса и чтение БД) | приёмочный тест `@pytest.mark.acceptance("kognis-8f1", "AC1")` |
| AC2 | Запись открывается в браузере правильным паролем; неверный пароль — понятная ошибка | приёмочный тест `@pytest.mark.acceptance("kognis-8f1", "AC2")` |
| AC3 | Приватные записи никогда не передаются в анализ | приёмочный тест `@pytest.mark.acceptance("kognis-8f1", "AC3")` |
| AC4 | Нет регрессий, интерфейс проверен глазами (`just shot`) и axe | `just verify` |
