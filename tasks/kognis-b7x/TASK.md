# TASK kognis-b7x: i18n 2/6 — коды ошибок сервера вместо фраз, язык пользователя в профиле

- **Тип:** risky (публичный контракт API, схема данных, профиль пользователя)  · **Приоритет:** P2  · **Бюджет:** $8  · **Автор:** jusk-one  · **Дата:** 2026-09-30

## 1. Цель
Kognis готовится к переводу на en/es/fr (переводы не делаем — только основа). Сервер перестаёт отдавать
русские фразы: ошибка для человека — код и параметры, текст берёт интерфейс из словаря; язык пользователя
хранится в профиле (`locale`) и приходит из `/api/me`.

## 2. Границы
- **Входит:** исключения домена с полем `code` (`kognis.errors`), ответ `{"detail": {"code", "params"}}` для всех
  ошибок API для человека (HTTPException, 4xx/5xx-обработчики, лимиты, ошибки ИИ и замка); словарь фронтенда
  `error.<code>` и общий текст для неизвестного кода; поле `users.locale` (миграция expand), `PUT /api/me/settings`
  принимает `locale`, регистрация берёт `Accept-Language`; фронтенд берёт язык из `/api/me`; `api.gen.ts`.
- **Не входит:** переводы, вынос текста страниц (следующие задачи серии), письма/уведомления.
- **Затрагиваемые модули:** `users`, `diary`, `analysis`, `ai`, `gameplay`, `web`, общий `kognis.errors`, `frontend`.

## 2a. Область влияния
- **Модули:** `src/kognis/*` (исключения), `web` (ответы), `users` (locale), `frontend/src` (api, i18n, errors).
- **Публичные интерфейсы:** тело ошибок API меняется со строки на объект — клиент один (фронтенд), выкатывается вместе; `UserOut.locale`, `SettingsIn.locale`.
- **Данные:** новая колонка `users.locale` (nullable, по умолчанию `ru`).
- **Что может сломаться:** тесты, читавшие фразы; e2e-тексты ошибок (регистр первой буквы — из словаря).
- **Проверки совместимости:** `just verify`, IDOR/security-тесты, миграционный тест.
- **Нужны ADR / миграция:** миграция да (expand), ADR нет.
- **Решения человека:** описание задачи в bd (2026-09-30, владелец): контракт API меняется, обратная совместимость не нужна.

## 2b. Эволюция
- **Схема:** users + `locale VARCHAR(16) NULL DEFAULT 'ru'`; существующие строки получают `ru`.
- **Совместимость на время обновления:** expand: колонка nullable, код читает `NULL` как `ru`.
- **Проверка на данных прошлой версии:** тест `@pytest.mark.migration` вверх/вниз.
- **Восстановление:** `alembic downgrade` (удаляет колонку).

## 2c. Угрозы
| Угроза (кто и как) | Мера | Тест |
|---|---|---|
| Чужой профиль читает/меняет `locale` | поле только у своего профиля (текущий пользователь из сессии) | security-тесты (AC4) |
| Ввод произвольного `locale` (мусор, длинная строка) | белый список кодов, 422 с кодом | AC3 |
| `Accept-Language` как вектор инъекции | разбор → только поддерживаемый код, иначе `ru` | AC3 |
| Текст исключения утекает наружу | наружу только код и параметры | AC1 |

## 3. Критерии приёмки
| # | Критерий | Как проверить |
|---|---|---|
| AC1 | Каждый маршрут, возвращающий ошибку человеку, отдаёт `detail.code`; в `src/` нет русских фраз в исключениях | `tests/web/test_error_codes.py` |
| AC2 | Фронтенд показывает текст по коду, неизвестный код → общий текст с HTTP-статусом | `tests/web/test_error_codes.py` (vitest `errors.test.ts`) |
| AC3 | locale: миграция вверх/вниз, PUT отклоняет неподдерживаемый код (422 с кодом), регистрация берёт Accept-Language | `tests/users/test_locale.py` |
| AC4 | Новые поля только у своего профиля (security-тесты зелёные) | `tests/security/test_locale_access.py` |

## 4. Ограничения
Смысл и вид интерфейса не меняются: тексты те же (первая буква ошибок теперь заглавная — из словаря).
Долг перевода `i18n_hardcoded` уменьшается (`just ratchet-up` делает `task-done`).

## 5. Риски
| Риск | Вероятность | Влияние | Мера |
|---|---|---|---|
| Пропущена фраза в одном из обработчиков | сред | русский текст в API | AST-тест на `raise` с кириллицей, тест на каждый маршрут |
| Код без записи в словаре | сред | «ошибка N» вместо текста | тест: каждый код из `src/` есть в `ru.ts` |

## 6. Неизвестные, гипотезы и эксперименты
Критичных неизвестных нет.
