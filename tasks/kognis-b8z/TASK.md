# TASK kognis-b8z: Архитектура и первый сквозной сценарий

- **Тип:** risky · создаётся автоматически для нового проекта профиля M · **до расширения приложения**

## 1. Цель
Проверить основные архитектурные предположения одним работающим путём через всю систему,
прежде чем добавлять функции.

**Продукт (от заказчика):**
Kognis — веб-портал «дневник переживаний» с ИИ-анализом и игровой механикой.

Для кого: взрослые, которые хотят лучше понимать свои эмоции и поведение; от новичков (простой режим)
до опытных пользователей (Advanced-режим).

Основные сценарии:
1. Регистрация и вход, личный аккаунт; данные пользователя видит только он.
2. Дневник: записи о переживаниях и событиях дня (текст, теги, эмоции); в конце дня — оценка самочувствия
   и настроения (шкалы) + короткая рефлексия.
3. Защита записей паролем, два режима на выбор для каждой записи:
   - «приватная» — шифруется в браузере (ключ из пароля, AES-GCM); сервер и ИИ её не видят; забытый пароль = потеря записи;
   - «под замком» — хранится зашифрованной ключом сервера, открывается отдельным паролем; ИИ-анализ — только
     после явного разрешения пользователя.
4. ИИ-анализ за выбранный период: суммаризация, динамика настроения, поведенческие паттерны по проблемам,
   которые описывает человек, с точки зрения разных направлений психологии (КПТ, ACT, схема-терапия,
   позитивная психология и др. — пользователь выбирает направление); ИИ задаёт уточняющие вопросы, если
   данных не хватает.
5. Схемы решения проблем в игровой форме: квесты (цепочки маленьких шагов), челленджи, квизы-рефлексии;
   прогресс сохраняется.
6. Игровая механика, которая мотивирует: опыт и уровни, серии дней (streaks), достижения, награды за
   рефлексию и выполненные шаги квестов.
7. Современный понятный интерфейс, тёмная тема, простой режим по умолчанию и Advanced-режим (графики,
   фильтры, настройки анализа, выбор направления психологии).

Ограничения и требования:
- Стек: веб-приложение (FastAPI + PostgreSQL + React/TypeScript) из шаблона.
- ИИ — сменный провайдер через адаптер: DeepSeek (Ollama Cloud) по умолчанию, позже локальная модель или
  Claude; в тестах — детерминированный фейковый провайдер. Сырые записи уходят к провайдеру только с согласия.
- Это не медицинский сервис: дисклеймер; при признаках кризиса (суицидальные мысли и т. п.) — не игровая
  механика, а контакты помощи.
- Приватность: персональные и чувствительные данные, минимум логирования содержимого записей.
- Архитектура должна позволить позже добавить тарифы и платные функции (проверка доступа к функциям
  по плану), мотивирующие рекомендации и новые модули — без переделки ядра.

Не нужно сейчас: оплата и тарифы, мобильное приложение, соцфункции, интеграции с внешними сервисами.

## 2. Границы
- **Входит:** заполнить `docs/ARCHITECTURE.md` (сценарии, модули и владение данными, интеграции, НФТ,
  вероятные изменения, рискованные предположения); выбрать стек (ADR); реализовать сценарий U1 сквозным путём:
  входной запрос / действие → бизнес-логика → сохранение данных → проверяемый результат.
- **Не входит:** остальные сценарии, интерфейс сверх необходимого для U1, оптимизация.
