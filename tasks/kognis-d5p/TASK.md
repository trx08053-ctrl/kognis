# TASK kognis-d5p: Безопасность: IDOR-тесты и аудит по чек-листу SECURITY.md

- **Тип:** risky · **Приоритет:** P0 · **Автор:** jusk-one (техответственный) · **Дата:** 2026-09-29

## 1. Цель
Доказать тестами, что пользователь не может прочитать или изменить чужие данные, и закрыть уязвимости,
которые найдёт аудит по `docs/SECURITY.md`. Новый слой безопасности harness показал: у 10 маршрутов с
идентификатором нет теста доступа к чужому ресурсу (tests/security/test_access.py).

## 2. Границы
- **Входит:** IDOR-тесты `@pytest.mark.security("idor", "<METHOD> <path>")` для каждого маршрута из списка
  `test_routes_with_ids_have_idor_tests` (пользователь B → 404 на объект A, объект A не изменился); аудит всего кода
  по чек-листу SECURITY.md (V2–V14): массовое присваивание, утечки полей (хэши, шифртекст, внутренние id) в ответах,
  сессии (выход, истечение), лимиты размера тела и списков, ошибки без внутренних деталей, логи, SSRF в ИИ-клиенте,
  CSP; исправление найденного; раздел 2c (угроза → мера → тест).
- **Не входит:** новые функции, изменение `security/public-routes.txt` (решение человека).

## 2a. Область влияния
- **Модули:** web, users, diary, analysis, gameplay (по находкам), tests · **Данные:** нет (если нужна миграция — объяснить)

## 2c. Угрозы
| Угроза (кто и как) | Мера | Тест |
|---|---|---|
| Пользователь B читает/меняет объекты A по id (IDOR) | фильтр по владельцу в запросе к БД, чужой объект → 404 | `tests/security/test_idor.py` (10 маршрутов), AC1 |
| Утечка хэшей, шифртекста замка, токенов в ответах | явные схемы `*Out` без служебных полей | AC2 |
| Огромное тело/списки → исчерпание ресурсов | `BodyLimitMiddleware` (512 КБ → 413), `max_length` в схемах, доменные лимиты | AC3, `test_domain_limits.py` |
| Необработанное исключение раскрывает внутренности | глобальный обработчик → общий 500 | `tests/security/test_errors.py` |
| SSRF через ИИ-клиент | URL провайдера только из окружения (аудит) | — (проверено чтением кода) |
| Кража/повтор сессии | httpOnly+Secure+SameSite, токен в БД хэшем, выход удаляет, срок 30 дней (аудит) | существующие тесты users |

## 3. Критерии приёмки
| # | Критерий | Как проверить |
|---|---|---|
| AC1 | Для каждого маршрута с {id} есть IDOR-тест: чужой объект → 404, данные владельца не изменились | `tests/security/test_access.py` зелёный; приёмочный тест `@pytest.mark.acceptance("kognis-d5p", "AC1")` на один сквозной сценарий A/B |
| AC2 | Ответы API не содержат хэшей паролей, шифртекста замка, токенов сессий и чужих данных | приёмочный тест `@pytest.mark.acceptance("kognis-d5p", "AC2")` по всем GET-ответам после наполнения данными |
| AC3 | Тело запроса больше лимита и слишком длинные списки отклоняются (413/422), сервер не падает | приёмочный тест `@pytest.mark.acceptance("kognis-d5p", "AC3")` |
| AC4 | Находки аудита исправлены или оформлены в TECH_DEBT/bd с обоснованием; раздел 2c заполнен | ревью |
| AC5 | `just verify` зелёный, включая sast и deps | evidence |
