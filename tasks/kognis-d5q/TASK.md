# TASK kognis-d5q: Безопасность пользователя: кризисные сигналы и контакты помощи

- **Тип:** risky · **Приоритет:** P2 · **Автор:** jusk-one (техответственный, ночное делегирование) · **Дата:** 2026-09-29
- Решения, на которые опирается задача: `docs/DECISIONS-NIGHT.md`, ADR в `docs/adr/`.

## 1. Цель
Если человек пишет о суицидальных мыслях или угрозе жизни, приложение не играет с ним в игру, а показывает контакты помощи.

## 2. Границы
- **Входит:** модуль safety: локальный детектор фраз (RU/EN, данные-конфигурация, без ИИ), контакты помощи (по умолчанию 112, конфигурация); при сохранении записи с сигналом — ответ с блоком помощи, запись помечается; публичная функция для анализа и gameplay; дисклеймер «не медицинская помощь» в интерфейсе.
- **Не входит:** классификация моделью, уведомление третьих лиц.

## 2a. Область влияния
- **Модули:** safety, diary, web, frontend · **Данные:** флаг кризиса у записи
- **Что может сломаться:** вход и записи (U1), изоляция данных пользователей — регрессионные тесты должны остаться зелёными

## 3. Критерии приёмки
| # | Критерий | Как проверить |
|---|---|---|
| AC1 | Запись с кризисной фразой (набор из фикстуры, RU и EN) сохраняется и возвращает блок помощи; интерфейс показывает его заметно и доступно | приёмочный тест `@pytest.mark.acceptance("kognis-d5q", "AC1")` |
| AC2 | Обычные записи (набор из фикстуры, в т.ч. «умираю от смеха») не вызывают ложной тревоги | приёмочный тест `@pytest.mark.acceptance("kognis-d5q", "AC2")` |
| AC3 | Запись с сигналом не даёт XP (когда игровое ядро готово) — публичный API safety позволяет это проверить | приёмочный тест `@pytest.mark.acceptance("kognis-d5q", "AC3")` |
| AC4 | Нет регрессий, интерфейс проверен глазами (`just shot`) и axe | `just verify` |
