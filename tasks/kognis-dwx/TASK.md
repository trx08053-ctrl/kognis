# TASK kognis-dwx: Фронтенд: разделить App.tsx по страницам, типы API из схемы бэкенда

- **Тип:** standard · **Приоритет:** P1 · **Автор:** jusk-one (техответственный, ревью реализации) · **Дата:** 2026-09-29

## 1. Цель
Фронтенд так же сопровождаем, как бэкенд: страница — файл, типы ответов API не расходятся с бэкендом.
Ревью реализации: `frontend/src/App.tsx` — 1567 строк и 29 компонентов (проверка `size`: ≤ 500), типы в
`api.ts` написаны вручную (сейчас совпадают со схемой, но ничто этого не гарантирует), покрытие ветвлений 60 %.

## 2. Границы
- **Входит:** разделить `App.tsx`: `pages/` (Auth, Home, Diary, DayReview, Analysis, Quests, Profile),
  `components/` (общие: чипы, шкалы, ошибки, прогресс), `App.tsx` — только маршруты и оболочка; поведение,
  подписи, `data-testid` не меняются. `api.ts`: типы ответов — только из `api.gen.ts`
  (`components["schemas"]["…"]`, `just api-types`), ручные интерфейсы ответов удалить. Тесты компонентов для
  непокрытых ветвлений (ошибки загрузки, пустые состояния).
- **Не входит:** изменение дизайна, API, бэкенда.

## 2a. Область влияния
- **Модули:** frontend; `web` — только тест структуры `tests/web/test_frontend_structure.py` (маркер `source`; код бэкенда не меняется). Страницы «Diary» отдельной нет: дневник = `HomePage` + `pages/home/*` · **Данные:** нет · **Что может сломаться:** все экраны — e2e и vitest должны остаться зелёными без правки сценариев
