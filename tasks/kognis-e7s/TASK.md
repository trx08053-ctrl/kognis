# TASK kognis-e7s: Эксплуатация: /health с проверкой БД, документация API только в dev, RUNBOOK

- **Тип:** standard · **Приоритет:** P1 · **Автор:** jusk-one (техответственный, ревью готовности к эксплуатации) · **Дата:** 2026-09-29

## 1. Цель
Приложение честно сообщает о своём состоянии, не раскрывает лишнего в проде, а инструкции эксплуатации
работают. Ревью: `/health` отвечает 200 при недоступной БД (деплой и healthcheck пройдут со сломанной базой);
`/docs`, `/redoc`, `/openapi.json` открыты всем в проде; в RUNBOOK команды бэкапа никогда не запускались и
неверны (проект compose `kognis-staging`, а не `kognis-stage`; нет файла с паролем БД) — теперь есть
`just backup` / `just restore` (harness).

## 2. Границы
- **Входит:** `/health` выполняет `SELECT 1` и при ошибке БД отвечает 503 (без деталей); документация API и
  схема OpenAPI — только при `KOGNIS_ENV=dev` (генератор типов фронтенда `scripts/gen_api_types.py` получает
  схему напрямую из `create_app(...).openapi()` — проверь, что `just api-types`/`contract` работают); RUNBOOK:
  удалить ручные команды бэкапа, оставить `just backup`/`just restore` из раздела harness, добавить ключ
  данных и порядок «бэкап перед деплоем со схемой».
- **Не входит:** мониторинг, алерты, ротация ключа.

## 2a. Область влияния
- **Модули:** web, docs · **Данные:** нет · **Что может сломаться:** e2e/staging используют /health; contract

## 3. Критерии приёмки
| # | Критерий | Как проверить |
|---|---|---|
| AC1 | При недоступной БД `/health` → 503 без внутренних деталей; при доступной → 200 | приёмочный тест `@pytest.mark.acceptance("kognis-e7s", "AC1")` |
| AC2 | Вне dev `/docs`, `/redoc`, `/openapi.json` → 404; при `KOGNIS_ENV=dev` доступны; `contract` зелёный | приёмочный тест `@pytest.mark.acceptance("kognis-e7s", "AC2")` |
| AC3 | В RUNBOOK нет ручных команд `docker compose … pg_dump/pg_restore`; бэкап и восстановление — `just backup`/`just restore` | приёмочный тест `@pytest.mark.acceptance("kognis-e7s", "AC3")` (маркер `source`) |
