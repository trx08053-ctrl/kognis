# TASK kognis-ox4: [bug] Искры: гонка покупок на SQLite уводит баланс в минус

- **Тип:** standard  · **Приоритет:** P1  · **Бюджет:** $2 / 2 ч  · **Автор:** jusk-one  · **Дата:** 2026-10-07

## 1. Цель
Параллельные покупки при балансе на одну могут увести баланс искров в минус: на SQLite проверка баланса
и списание не атомарны (`_lock_owner` берёт `pg_advisory_xact_lock` только на Postgres). Тест
`test_concurrent_purchases_never_go_negative` это ловит недетерминированно (упал в CI на ветке
kognis-2zb: `assert -50 >= 0`) и блокирует land. Сделать инвариант «баланс неотрицателен» выполняемым
на обоих диалектах и воспроизводимым тестом.

## 2. Границы
- **Входит:** `gameplay/_sparks_infra.py` (`_lock_owner`), усиление теста барьером + маркер AC1; возможно
  запись в TECH_DEBT, если ограничение останется.
- **Не входит:** переписывание механики искров, Postgres-миграции, веб-API.
- **Затрагиваемые модули:** `src/kognis/gameplay`, `tests/web/test_sparks.py`.

## 2a. Область влияния (одной строкой)
- **Модули:** `src/kognis/gameplay` — сериализация покупок на SQLite; `tests/web` — воспроизводимость гонки.
- **Публичные интерфейсы:** нет. **Данные:** нет. **ADR/миграция:** нет.
- **Что может сломаться:** конкурентные покупки; проверки совместимости — `test_sparks.py` (AC1 kognis-crn).
- **Решения человека:** нет (блокер land обеих веток; владелец запросил влитие).
